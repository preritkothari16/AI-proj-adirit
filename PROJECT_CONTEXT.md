# Zombie Darwin — Project Context

## Project Goal
University AI project (2 devs, 4 weeks). Top-down wave-survival game on a 32×20 grid: 10 waves × 20 zombies, max 60 s per wave. Player moves, shoots, places barricades. Zombies evolve between waves via GA; Hill Climbing + Random Search are baselines. Goal: demonstrate AI syllabus concepts inside a playable game.

## Important Interfaces
(Frozen in P1.2 — implemented, not stubs, unless noted. Change only by agreement.)

- `ai/genome.py`: `Genome(genes: np.ndarray)` shape (6,), floats [0,1], order = `GENE_NAMES` = speed, health, vision, aggression, path_strategy, swarm. `__post_init__` casts to `np.float64` and raises `ValueError` on wrong shape. `Genome.of(**genes)` builds by name (unspecified = 0.5, `path_strategy` may be a `PathStrategy`, unknown name → `ValueError`); `genome[name]`. `decode() -> ZombieStats` (P3.4): clips genes to [0,1], then speed/health/vision/aggression lerp over `ZOMBIE_SPEED_RANGE` (40–140) / `ZOMBIE_HP_RANGE` (10–90) / `ZOMBIE_VISION_RANGE` (128–384) / `ZOMBIE_GIVE_UP_RANGE` (1–5 s, aggression → `give_up_time`); path_strategy gene in 3 equal bins DIRECT/GREEDY/ASTAR (`strategy_from_gene`, inverse `strategy_gene` = bin centre); `swarm_weight = swarm * ZOMBIE_SWARM_WEIGHT_MAX` (1.0). All-0.5 = old dummy (90 px/s, 50 HP, 256 px, 3 s). `Genome.random(rng, budget=STAT_BUDGET)`: `rng.random(6)` then `repair` — deterministic per rng state, uses only the given rng. `repair(budget=STAT_BUDGET) -> Genome` (new object, self untouched): NaN → `ValueError`, budget outside [0,3] → `ValueError`; clip all genes to [0,1] (±inf clip too); then `BUDGET_GENES` (speed, health, vision) rescaled to sum exactly to budget keeping ratios — scale down proportionally; scale up proportionally, capping at 1 and redistributing the rest among uncapped genes; all-zero stats split evenly. aggression/path_strategy/swarm only clipped. Idempotent. `budget_used()` = speed+health+vision genes. Budget param exists for P5.7 sweeps. `PathStrategy(Enum){DIRECT, GREEDY, ASTAR}`. `ZombieStats` frozen dataclass: `speed, max_hp, vision_radius, give_up_time, path_strategy, swarm_weight`.
- `ai/fitness.py`: `FitnessStats(damage_dealt=0.0, time_alive=0.0, min_dist_to_player=inf, reached_player=False)`. `compute_fitness(stats) -> float` (P4.5): `W_DAMAGE*damage + W_PROXIMITY*proximity + W_SURVIVAL*survival + W_REACHED*reached`, each term in [0,1]: damage = `damage_dealt/FITNESS_DAMAGE_REF` (=`PLAYER_MAX_HP`), proximity = `1 - min_dist/FITNESS_DISTANCE_REF` (=map width px; inf → 0), survival = `time_alive/WAVE_TIME_LIMIT`, reached = 0/1; terms capped, weights 0.5/0.25/0.1/0.15 sum to 1 → fitness in [0,1]. Negative/NaN stats → `ValueError`. Units: `min_dist_to_player` = body gap px (0 = touching), `time_alive` s. `Zombie.fitness_stats: FitnessStats` (updated each living tick at end of `update`; `time_alive` from a tick counter, stops at death; `reached_player` = ever `in_contact`); `Zombie.damage_dealt` is now a read-only property onto it.
- `game/states.py`: `ZombieState(Enum){WANDER, CHASE, SEARCH, ATTACK}`, `FSMInputs` frozen dataclass: `sees_player, dist_to_player, time_since_seen, give_up_time, attack_range`. `next_state(state, inputs) -> ZombieState` — pure. In range = `dist_to_player <= attack_range` (caller picks units; P3.x passes body gap px + `ZOMBIE_ATTACK_REACH`). WANDER→CHASE on sight; CHASE→ATTACK in range, →SEARCH on lost sight; ATTACK stays while in range (even unseen), else →CHASE if visible / →SEARCH if not; SEARCH→CHASE on sight (beats give-up), →WANDER when `time_since_seen >= give_up_time`. WANDER never jumps straight to ATTACK. Unknown state → `ValueError`.
- `game/player.py`: `Body(pos, tile_size, speed, radius)` — shared base for Player and Zombie: `x, y, pos, speed, radius, move(direction, dt, is_blocked)`, `occupied_tiles()`; tunnelling guard raises `ValueError` if `speed*FIXED_DT >= tile_size`. `Action` frozen dataclass: `move=(0,0), aim=(0,0), shoot=False, barricade=None`. `Controller` is a `@runtime_checkable Protocol` with `get_action(self, world) -> Action`. `Player(Body)(pos, tile_size, speed=PLAYER_SPEED, max_hp=PLAYER_MAX_HP, radius=PLAYER_RADIUS)`: adds `hp, max_hp, alive, take_damage(amount)` (HP clamped at 0), fire cooldown; `move(direction, dt, is_blocked: Callable[[Tile], bool])` — normalises vectors longer than 1 (diagonals not faster), smaller magnitudes kept as-is.
- `game/map.py`: `TileMap` frozen dataclass — `TileMap.load(path, tile_size=32)`, `width, height, tile_size`, `walls: frozenset[Tile]`, `spawn_points: tuple[Tile, ...]`, `player_start: Tile`. `is_walkable(t)` (bounds + not a wall), `in_bounds(t)`, `neighbors(t)` (4-dir N/S/E/W, walkable only), `world_to_tile(pos)` (floor-div by `tile_size`), `tile_to_world(t)` (tile *centre*, not corner). `has_line_of_sight(a, b, is_blocked=None) -> bool` — tile-centre to tile-centre, every touched tile must be clear (endpoints included); `is_blocked` defaults to walls + OOB. `load()` raises `ValueError` on: ragged rows, unknown chars, 0 spawns, 0 or 2+ player starts. Tile = `tuple[int, int]` (col, row).
- `ai/pathfinding.py`: works on any `GraphLike` (structural `Protocol`, just needs `neighbors(tile) -> Iterable[Tile]`) — does **not** import `game.map`, satisfying the import-direction rule; `TileMap` satisfies it duck-typed. `manhattan(a, b) -> int`. `astar(graph, start, goal, stats=None) -> list[Tile] | None`, `greedy_best_first(graph, start, goal, stats=None) -> list[Tile] | None` — pass a `dict` as `stats` to get `stats['nodes_expanded']` after the call (added for P5.6 experiments; return type unchanged, so existing calls don't need it). `is_reachable(graph, starts: Iterable[Tile], goal) -> bool` — BFS, True only if **every** tile in `starts` reaches `goal` (used for barricade validation, P2.5).
- `game/barricade.py`: `check_placement(world, tile, max_barricades=MAX_BARRICADES) -> PlacementResult` (pure, no mutation). `PlacementResult(Enum){OK, INVALID_TILE (OOB/wall/spawn), OCCUPIED (already barricaded / under player's or any zombie's hitbox), LIMIT_REACHED, BLOCKS_PATH}` — checks run in that order. `all_spawns_connected(world)` helper.
- `game/zombie.py`: `Zombie(Body)(zid, genome, pos, tile_size=TILE_SIZE)` — `stats = genome.decode()` gives `speed, max_hp, vision_radius, give_up_time, path_strategy, swarm_weight`; radius / attack damage / cooldown / reach are shared config. Keeps `zid, genome, stats`. `swarm_force(world) -> (fx, fy)`. `hp, max_hp, alive, take_damage()`, `damage_dealt`, `gap_to(player)`, `in_contact(player)`, `sees_player(world)` (≤ `vision_radius` px centre-to-centre AND `world.has_line_of_sight` between tiles). FSM state: `state`, `last_known_pos` (px), `ticks_since_seen` / `time_since_seen` (inf if never), `wander_target`. Navigation: `path`, `path_goal`, `repaths`, `nodes_expanded`. `update(dt, world)`: perceive → `next_state` → act (WANDER random floor tile via `world.rng`, CHASE player, SEARCH `last_known_pos` then wait, ATTACK hit on cooldown, standing still).
- `game/engine.py`: `World(tilemap, rng)` — `rng` must be `np.random.Generator`. Attributes: `tilemap`, `rng`, `player: Player` (spawned at centre of `player_start`), `zombies: list[Zombie]`, `bullets: list[Bullet]`, `barricades: set[Tile]`, `tick`, `last_action`, `last_placement: PlacementResult | None`. `time` = `tick * FIXED_DT`. `is_blocked(tile)` = wall, out of bounds, or barricade. `neighbors(tile)` = 4-dir unblocked tiles, so **World is a `GraphLike`** — zombies path over `world`, not `tilemap`. `place_barricade(tile) -> PlacementResult`. `spawn_zombie(tile, genome) -> Zombie` (sequential `zid`s from 0). `has_line_of_sight(a, b)` = tilemap LOS with `is_blocked` (barricades block sight). `game_over` = player HP 0. `step(action)`: no-op once `game_over`; else place barricade if `action.barricade` → move player → fire if `action.shoot` and cooldown ready (toward `action.aim`, a world-pixel point; no shot if aim == player centre) → update bullets (segment-vs-circle hit test on each bullet's per-tick path; first zombie hit takes `bullet.damage`, bullet dies) → drop dead bullets and zombies → zombies update (move/attack) → tick += 1.
- `game/session.py` (P4.7): `GameSession(tilemap, seed=0, num_waves=NUM_WAVES, wave_time_limit=WAVE_TIME_LIMIT, optimizer_factory=GeneticAlgorithm)`. `Phase{MENU, WAVE, REPORT, VICTORY, GAME_OVER}`. `start()` (MENU/VICTORY/GAME_OVER → wave 1 of a fresh run, else `RuntimeError`), `next_wave()` (REPORT only), `step(action)` (WAVE only; steps `world` then `wave_manager.update`, finishes wave when over). Attributes: `phase, wave` (1-based), `world` (**new World each wave**: full-HP player, no barricades, tick 0), `wave_manager`, `genomes` (current/upcoming population), `history: list[WaveReport]`, `last_report`, `zombies_total/remaining`, `time_left`, `population_summary`. On wave end: fitness = `compute_fitness` per result → `WaveReport` → if player alive and waves remain, `optimizer.next_generation(genomes, fitnesses)`; player dead → GAME_OVER (no evolution); last wave survived → VICTORY. `WaveReport(wave, end_reason, time, zombies_total, zombies_killed, player_hp, player_max_hp, best/mean/worst_fitness, mean_damage, fought: PopulationSummary, evolved: PopulationSummary | None)`. `PopulationSummary(size, mean_speed, mean_hp, mean_vision, mean_swarm, strategy_counts)`; `summarize(genomes)`. Rng: `SeedSequence(seed).spawn(2)` → separate world and optimizer streams. `game/renderer.py`: `Renderer.draw(surface, world, session=None)`; pure text helpers `status_line`, `evolution_line`, `traits_text`, `screen_text(session) -> (title, lines) | None`. `main.handle_keydown(session, renderer, key) -> bool`.
- `game/wave_manager.py` (P4.6): `WaveManager(world, time_limit=WAVE_TIME_LIMIT)`. `start_wave(genomes) -> list[Zombie]`: empty → `ValueError`, non-Genome → `TypeError`, dead player → `ValueError`; clears `world.zombies`/`bullets` (barricades, player untouched), spawns one zombie per genome in genome order; spawn slot i → `spawn_points[i % n]` where slots are a `world.rng.permutation` (even spread, ±1 per point, random genome→point so GA elites don't always share a spawn). `update(world=None)`: call after each `world.step`; latches `end_reason: WaveEnd | None` (`PLAYER_DEAD` > `ALL_DEAD` > `TIME_UP`; time = `world.tick - start_tick >= limit_ticks`, tick-counted). `is_over()`, `results() -> list[(Genome, FitnessStats snapshot)]` in input order, includes dead zombies (manager keeps `wave_zombies` since World drops dead ones), valid mid-wave. Info: `ticks_elapsed`, `time_elapsed`, `time_left`, `alive_count`. Calling `is_over/results/update` before `start_wave` → `RuntimeError`. Caller owns the loop (`world.step` then `wm.update`).
- `ai/genetic.py`: `Optimizer` (`@runtime_checkable Protocol`): `initial_population() -> list[Genome]`, `next_generation(genomes, fitnesses) -> list[Genome]` (same length; fitness higher = better; length mismatch / empty / NaN → `ValueError`; input not modified). `GeneticAlgorithm(rng, population_size=POPULATION_SIZE, tournament_size=TOURNAMENT_SIZE, elitism=ELITISM_COUNT, crossover_rate, mutation_rate, mutation_sigma, budget=STAT_BUDGET)`. Pure operators: `elite_indices(fit, k)` (best first, ties → earlier index), `tournament_select(fit, rng, size)` (distinct contestants, capped at pop size, ties → earlier), `uniform_crossover(a, b, rng, rate) -> (c1, c2)` (prob `rate`: fair coin per gene, c2 = complement; else copies), `mutate(g, rng, rate, sigma)` (each gene w.p. rate += N(0, sigma); **unrepaired**). `RandomSearch(rng, population_size, budget)`: fresh `Genome.random` population every generation, fitness validated but ignored. `ai/toy_benchmark.py`: `TOY_TARGET` (valid genome), `toy_fitness(target) -> Callable[[Genome], float]` (= −Euclidean gene distance), `run(optimizer, fitness, generations) -> RunResult(best_so_far, mean_per_generation, best_genome, evaluations)`, `compare(seeds, generations)` over `OPTIMIZERS` dict (GA, Random, HC). `ai/hill_climbing.py`: `HillClimber(rng, population_size=POPULATION_SIZE, sigma=MUTATION_SIGMA, budget=STAT_BUDGET)` — `current: list[Genome]`, `current_fitnesses` (one per climber; empty until first `next_generation`, reset by `initial_population`); `neighbour(g)` = `mutate(rate=1, sigma)` + repair. **Stateful**: `next_generation` must receive the population it last returned (size change → `ValueError`). All take `rng`.

## Architectural Decisions
- **Only `main.py` and `game/renderer.py` import pygame.** Why: headless sim + tests need no window.
- **Import direction: `ai/` pure modules (pathfinding, genome, fitness, genetic, hill_climbing) never import `game/`.** Only `ai/bot_player.py` may. Why: avoids circular imports, lets B test in isolation.
- **Fixed timestep (FIXED_DT = 1/60) + seeded `np.random.Generator` passed in.** Why: reproducible, headless == rendered.
- **Human and bot share `Controller -> Action`.** Why: BotPlayer is drop-in.
- **Genes in [0,1]; speed+health+vision share a fixed stat budget (`repair()`), sum == budget exactly (not ≤).** Why: forces trade-offs; otherwise GA maxes everything. Exact sum (per config comment) means no zombie wastes points and the budget experiment compares like with like; ratio-preserving rescale keeps the genome's "shape" (which stat it favours). Non-stat genes are behaviours, so free.
- **GA generation (P4.2):** elites (top `ELITISM_COUNT`=2, copied unchanged, first in the list) → repeat: 2 tournament parents (size 3) → uniform crossover (0.9) → mutate each child (per gene 0.1, Gaussian σ=`MUTATION_SIGMA`=0.1, new config) → `repair(budget)`; odd leftover slot drops the 2nd child. Population size = input size. All randomness via the passed `rng`. Why: textbook operators, each unit-testable; Gaussian (not uniform reset) keeps mutation local so evolution is gradual and visible across waves; repair after mutation keeps every genome valid.
- **Toy benchmark (P4.3):** per seed each optimizer gets `default_rng(seed)` → identical initial populations, same pop size × generations = same evaluations; metric = best fitness so far. Results (10 seeds, 50 gens): distance GA 0.008 vs Random 0.16; 30 seeds × 100 gens: GA 0.003 vs Random 0.17, GA wins 30/30. Why: proves the GA converges on a known optimum before trusting it on noisy game fitness.
- **Fitness (P4.5):** normalised weighted sum, all constants in `config.py` (`FITNESS_*`). Damage weighted highest, survival lowest so idle survivors can't beat fighters; proximity + reached give gradient before first hit. Why: raw HP/px/s aren't comparable; normalising makes weights meaningful. Weights are placeholders (P6.1).
- **WaveManager (P4.6):** doesn't step the world; caller does step → update. Why: keeps one clock owner (bot/human loop), same code path headless and rendered. Random genome→spawn assignment via world.rng. Player death beats all-dead beats timeout when simultaneous.
- **Game flow (P4.7):** logic in pygame-free `GameSession`, `main.py`/renderer only draw + map keys. Fresh World per wave (HP/barricades don't carry over) so every generation faces identical conditions; population evolves only if the player survives; restart (`start()`) keeps the seeded rng stream so the next run differs. HUD = top wall row (wave, time left, HP, zombies remaining/total) + bottom wall row (last wave best/avg fitness with delta, current population avg speed/HP/vision, A*/Greedy/Direct counts); between-wave report panel adds kills, damage, fitness spread, fought vs evolved traits, fitness trend. Observed vs an idle invulnerable player: fitness saturates near 1.0 from wave 1, avg speed climbs 85→137; expect lower with a fighting player — retune weights in P6.1.
- **`slow` pytest marker** (registered in pyproject.toml) for multi-seed statistical tests; runs by default, skip with `-m "not slow"`.
- **Common `Optimizer` interface; HC = 20 parallel hill climbers; RandomSearch baseline.** Why: fair comparison, same evaluation budget.
- **HillClimber (P4.4):** first evaluated population = starting points; afterwards candidate i replaces climber i only if **strictly** better (ties keep old, so no drift); each climber proposes one neighbour per generation = Gaussian σ=0.1 on **every** gene (per-gene 10 % like GA would waste ~half the evaluations on no-ops) then repair. No crossover, no sharing, no restarts. Toy (30 seeds × 50 gens): distance HC 0.055 vs GA 0.008 vs Random 0.18; HC beats Random 30/30. Why: textbook local search baseline — improves steadily but slower than GA.
- **`states.py` = zombie FSM (pure function), not screen states.** Screen states live in `main.py`. Why: FSM unit-testable without World.
- **`engine.py` holds `World` (logic), not the pygame loop.** Why: keeps pygame out of simulation.
- **Bullets = simple fast projectiles (`bullet.py`), not hitscan.** Why: matches target structure; circle collision is simple and visible.
- **Barricades indestructible, max `MAX_BARRICADES`=5; rejected if BFS (with the candidate added) finds any spawn cut off from the player's *current* tile. Pathfinding treats them as fully blocked (not high-cost) via `World.neighbors`; they also block bullets. Spawn tiles and tiles under the player can't be barricaded.** Why: simplest valid rule; blocked-not-costly keeps A*/Greedy unchanged, and the BFS check guarantees a path always exists.
- **Zombies repath on ~0.5 s timer or target tile change.** Why: performance in headless runs.
- **Swarm gene = one steering weight toward nearby allies' centroid.** Why: meaningful without full boids.
- **"Budget experiments" = sweep stat-budget size.** Why: tests how trade-off pressure changes evolved strategies.
- **`simulate.py` added at root** as headless CLI. Why: target had no home for the runner.
- **`ai/pathfinding.py` takes a structural `GraphLike` Protocol, not `TileMap` directly.** Why: enforces the "ai/ never imports game/" rule without losing type hints; `TileMap` satisfies it because it already has `neighbors()`.
- **Bullets are points moving each tick, sub-stepped every ≤ tile/4 px; die on blocked tile (walls + barricades) or leaving the map. Fire cooldown counted in whole ticks (`Player.cooldown_remaining`, 15 ticks = 0.25 s).** Why: no hitscan per plan; sub-stepping stops tunnelling; tick counters avoid float timing drift.
- **`main.py` uses a fixed-timestep accumulator (max 5 ticks/frame) around `world.step()`.** Why: simulation always advances in FIXED_DT regardless of real frame time, so play matches headless runs. `Renderer` pre-draws the static map once and only reads World. No camera: world px == screen px (1024×640).
- **Player collision = axis-aligned square (half-width `PLAYER_RADIUS`), resolved X then Y and clamped flush to the tile edge.** Why: simplest correct tile collision; per-axis resolution gives wall sliding for free. `Player.move` takes an `is_blocked` callable so it never needs World or pygame, and barricades block via `World.is_blocked`.
- **Attack rule (P2.6): contact = gap between player and zombie circles ≤ `ZOMBIE_ATTACK_REACH` (4 px). In contact the zombie stops and deals `ZOMBIE_ATTACK_DAMAGE`=10 every `ZOMBIE_ATTACK_COOLDOWN`=1 s (tick-counted). Zombies don't collide with each other or push the player.** Why: simplest rule that makes the player killable; later FSM ATTACK state reuses it. Radius 10 for all zombies; speed/HP now from genome (P3.4).
- **Line of sight = exact-integer supercover traversal between tile centres; at an exact corner both side tiles must be clear (no seeing through diagonal gaps or grazing wall corners). Barricades block sight.** Why: exact (no float edge cases), symmetric, conservative; consistent with barricades blocking bullets. Vision (P3.3) converts pixel positions with `world_to_tile` first.
- **Zombie perception/behaviour (P3.3):** starts in WANDER. FSM inputs: `dist_to_player` = body gap px, `attack_range` = `ZOMBIE_ATTACK_REACH` (so ATTACK ≡ in contact). WANDER picks a uniform random floor tile (via `world.rng`, deterministic per seed), re-picks on arrival, if unreachable, or after `ZOMBIE_WANDER_RETARGET`=6 s. SEARCH navigates to `last_known_pos` and waits there until `give_up_time` (genome, 1–5 s) after last sighting. Vision radius from genome (128–384 px). Why: simple, testable, deterministic; on level1 wandering zombies find an idle player in ~20 s median, most within a 60 s wave. Tests that only check navigation give zombies x-ray sight (`z.sees_player = lambda w: True`).
- **Zombie path following (P3.2):** Greedy/A* search over `world` (barricades = walls) from the zombie's tile to the target tile (player / last known / wander target); drop `path[0]` (own tile) and steer to each next tile centre, popping at ≤0.5 px (move vector scaled so the last step lands exactly). Re-plan when `ZOMBIE_REPATH_INTERVAL` (0.5 s, tick-counted) elapses, when the target tile ≠ `path_goal`, and on first update; no planning while attacking. Empty path (on target tile) → close in directly. Why: tile-centre movement keeps 4-dir paths clean; wall sliding absorbs the off-centre first leg; replanning on player tile change keeps chase tight and costs little (20 A* zombies ≈ 0.35 s wall per 60 s wave).
- **Swarm (P3.4):** each tick (not while attacking) the unit navigation direction gets `swarm_weight` × unit vector toward the centroid of living allies within `ZOMBIE_SWARM_RADIUS`=96 px (3 tiles) added; `Body.move` renormalises, so speed never exceeds the gene's speed. `swarm_weight` 0 → exactly zero force (trajectory identical to a lone zombie). A path waypoint counts as reached within `0.5 px + |swarm| × one step`, so the sideways pull can't stall path following. Why: one cheap, testable steering term matching the swarm-gene decision; O(n²) over ≤20 zombies is negligible.
- **Bullet↔zombie hits use the swept segment of each tick, not the end point.** Why: bullets can't skip zombies regardless of speed. One zombie per bullet (no piercing).
- **Debug overlay (P3.5):** `Renderer(world, debug=False)`, `toggle_debug()`; F1 in `main.py`, `python main.py --debug` starts with it on. Per zombie, in its state colour (`STATE_COLOURS`: WANDER grey, CHASE red, SEARCH orange, ATTACK purple): 1 px vision-radius circle; 2 px route = position → remaining `path` tile centres → final point (player / `last_known_pos` / wander tile; none while attacking), so DIRECT zombies show a straight line; X on `last_known_pos` in SEARCH; label "STATE strategy" under the body. Routes drawn under bodies, labels over. HUD adds "[F1] debug". Read-only. Why: shows every AI decision (state, planner, target, sight range) with no extra UI.
- **Game over freezes `World.step`.** Why: headless runs and the renderer can just check `world.game_over`. `main.py` has a temporary demo spawner (one `Genome.random(world.rng)` zombie per spawn every 6 s) until WaveManager (P4.6).
- **`stats: dict | None` out-param on `astar`/`greedy_best_first` for `nodes_expanded`**, instead of changing the return type. Why: keeps the frozen `list[Tile] | None` signature; P5.6 experiments opt in by passing a dict.
